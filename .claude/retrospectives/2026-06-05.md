## What got easier

- **Coverage gap workflow** — the pattern of (identify gap in backlog → write targeted test PR → measure → raise CI gate) now runs smoothly. Three gate raises in four days (75% → 80% → 81%) without any coverage regressions.
- **Action shipping** — new actions from initial spec to merged PR in one session. `claude.install`, `claude.upgrade`, `macos.rosetta`, `package.upgrade` all followed the `etch-cli-new-action` skill exactly.
- **Memory capture** — `testing-gotchas.md` (8KB) now holds a comprehensive reference for Rust/tarpaulin edge cases. New gotchas are captured same-session; the next session doesn't re-learn them.
- **PR velocity** — 0.3h median cycle time is stable across the whole 30-day period (71 PRs). The auto-merge + CI gate is working as intended.

## Recurring gotchas (action required)

- **Tarpaulin vtable dispatch** — tests through `Box<dyn Action>` don't count as covered. Needed memory file + standards update. → **Proposed action:** add a checklist item to the `etch-cli-new-action` skill reminding to use static dispatch in coverage tests, not trait-object wrappers.
- **`concat!()` for multiline Rust string literals** — `\<newline><whitespace>` strips indentation silently. Hit again this period (YAML content in tests). → **Proposed action:** already in `rust.md`; add a lint note to `etch-cli-new-action` skill for action test scaffolding.
- **`cavecrew-builder` can't run cargo/git** — builder edits files but returns diffs that require the main session to run `cargo check`, verify, and commit. Memory file captured, but the coordination is manual every time. → **Proposed action:** add a "verify after builder edits" step to whichever skill dispatches builder agents (currently ad hoc).
- **macOS vs Linux coverage discrepancy** — macOS tarpaulin sees more covered lines than Linux ptrace; the CI gate is Linux-only but local measurement is macOS. Developers (or Claude) raising the gate based on local numbers causes CI failures. → **Proposed action:** add a note to the coverage section of `CLAUDE.md` warning against raising the gate until Linux CI number is confirmed. (CLAUDE.md currently says "verify from CI output, not local macOS measurement" — it's there but ignored under pressure.)
