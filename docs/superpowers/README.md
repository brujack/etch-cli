## Backlog

| Feature                  | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ntfy notification action | Matches existing notification infra                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| powershell.module        | No action for installing PowerShell modules from PSGallery. Dotfiles install 10 modules (Az, AWSPowerShell.NetCore, Microsoft.Graph, oh-my-posh, etc.) via script. Needs `powershell.module` with `name:`, `scope: CurrentUser\|AllUsers`, idempotent via `Get-Module -ListAvailable`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| drift detection          | `etch status` command — compare declared manifest state against actual machine state without applying. Per-atom check: file.copy verifies content hash matches source, file.link verifies symlink target, file.chmod verifies permissions, package.install queries installed version, directory.create checks existence. Output: table of atoms with status `ok \| drifted \| missing`, similar to `terraform plan` output. **Why it matters:** currently no way to know if a machine has diverged from its manifest since last `etch apply` without running apply. Essential prerequisite for rollback (#3 and #4) since you need a baseline to roll back to. **Implementation shape:** new `StatusCommand` in `app/src/commands/`; add `status() -> Result<AtomStatus>` to the `Atom` trait alongside existing `plan()`/`apply()`. Each atom implements the check against live system state. Exit code 0 = clean, 1 = drift detected (CI-friendly). |
| version pinning          | Add `version:` field to `package.install` action. On apply: query installed version (e.g. `brew info --json name \| jq .versions.stable`, `apt-cache policy pkg \| grep Installed`), compare to declared version, fail with actionable error if mismatch. Without this, `package.install` is idempotent only on presence — two machines running the same manifest a month apart can have different package versions. **Scope:** brew and apt providers first (those are the active providers); snap has `--channel` which maps naturally. **Gotcha:** brew formula versions are not always pinnable without `brew pin`; need to decide whether etch calls `brew pin` or just validates. `binary.url` already has `version:` + `sha256:` — that pattern works and should be the model.                                                                                                                                                                 |
| state manifest           | Write `~/.local/share/etch/state.yaml` after each successful `etch apply` recording: manifest path, atom type, key fields (file path, package name), applied-at timestamp, and for file atoms a sha256 of the content written. `etch diff` compares current state file against live system (same checks as drift detection). Enables: (a) `etch history` showing when each atom last changed, (b) rollback target for file atoms (#4), (c) machine comparison — diff two state files to audit divergence. **Implementation shape:** `StateStore` struct in `lib/src/state/`; written atomically (temp file + rename) after apply to avoid partial writes on crash. State file is machine-local, not committed — distinct from manifests. **Dependency:** drift detection atoms need to exist first (shared `status()` impl).                                                                                                                          |
| file rollback            | Before `file.copy` or `file.link` overwrites a target, stash the original to `~/.local/share/etch/backups/<sha256-of-path>/<timestamp>`. `etch rollback [--manifest foo.yaml] [--atom file.copy:~/.zshrc]` restores the most recent stash for the specified atoms. Stash retention: keep last N versions (configurable, default 3) per path; prune on each apply. **Scope is intentionally narrow:** file atoms only. Package rollbacks require Nix's store model — not feasible without it. Brew has `brew extract + brew install pkg@ver` for some formulae but it's unreliable. **Risk:** if a user manually edits a stashed file's target between etch runs, the stash is stale — rollback would overwrite their manual change. Mitigate: show diff before restoring (dry-run rollback by default). **Dependency:** state manifest (#3) needed to know which stash corresponds to which apply run.                                                |

## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).
