## Backlog

| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `flatpak.install`                   | Install Flatpak apps from Flathub or other remotes. Needed to manage Steam (`com.valvesoftware.Steam`) and other Flatpak apps from etch-config. Fields: `app_id:`, `remote:` (default `flathub`), idempotent via `flatpak list`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Maintainability pass                | Once the ai-config maintainability gate (2026-07-24 spec) ships, run a worldclass pass in this repo against its thresholds — not scheduled yet.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Flip `missing_docs` to `warn`       | 402 undocumented public items as of 2026-08-02 (`make docs-debt` rechecks), concentrated in `etch-lib` — the only crate in either repo with a real cross-crate consumer and published metadata. Shipped at `allow` with a dated comment; this row is its expiry. Incidentally, `make docs-debt` is the only standing evidence that lint output is being produced at all — once the 45 `Debug` derives land, every `warn` lint finds zero again, so `docs-debt` is the one command in either repo whose output is non-zero. If a toolchain change silently stopped promoting `warn` to error, both `warn` lints would go green and stay green; a `docs-debt` count that drops to 0 without anyone documenting anything is the signal. |
| Make `cargo semver-checks` blocking | It runs today but cannot fail a PR: `ci.yml:158` sets `continue-on-error: true`, and `auto-merge` `needs: [test, cargo-audit, secret-scan, snyk-scan, docs-lint, docs-build]` excludes it. The blocker is `enum_variant_added` — `CLAUDE.md` documents that every new action adds a public enum variant, so the check is permanently red by construction. Fix is `#[non_exhaustive]` on the action enum (which makes variant addition non-breaking), then remove `continue-on-error` and add the job to `auto-merge needs:`. Not a config toggle — the `#[non_exhaustive]` change is itself semver-breaking and needs its own cycle.                                                                                                 |
| Close the `pre-push` Python trigger gap | `scripts/pre-push`'s pattern matches neither `scripts/*.py`, `tests/*.py`, `ruff.toml`, `Makefile`, nor `requirements-ci.txt`, so every Python-only or toolchain-only change skips the local hook and is gated on the CI side alone. Pre-existing (already noted in `CLAUDE.md`), but the pytest migration and the vendored rendering both widened what lands on the CI-only side. Fix is one regex in the hook plus a test that a Python-only staged change actually triggers it. |

## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).
