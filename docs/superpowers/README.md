## Backlog

| Feature                     | Notes                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ntfy notification action    | Matches existing notification infra                                                                                                                                                                                                                                                                                         |
| powershell.module           | No action for installing PowerShell modules from PSGallery. Dotfiles install 10 modules (Az, AWSPowerShell.NetCore, Microsoft.Graph, oh-my-posh, etc.) via script. Needs `powershell.module` with `name:`, `scope: CurrentUser\|AllUsers`, idempotent via `Get-Module -ListAvailable`.                                      |
| claude.plugin action        | setup_env.sh manages 13 Claude plugins (superpowers, code-review, context7, context-mode, rust-analyzer-lsp, pyright-lsp, caveman, firecrawl, etc.) via `claude plugins install/update`. No etch-cli action exists. Needs `claude.plugin` with `name:` and idempotency via `claude plugins list`. macOS + Linux.            |
| macos.softwareupdate        | No action for `softwareupdate --install --all`. setup_env.sh runs this during update workflow. macOS-only. Idempotency: always runs (softwareupdate is itself idempotent — no-ops if nothing to install).                                                                                                                   |
| oh-my-zsh action            | No action for oh-my-zsh install or custom plugin management. setup_env.sh installs via official curl installer (skips if `~/.oh-my-zsh` exists), then clones plugins (zsh-autosuggestions, etc.) into `~/.oh-my-zsh/custom/plugins/`. Could be `zsh.oh-my-zsh` with `plugins: [list]`.                                      |
| chruby action               | setup_env.sh uses chruby + ruby-install on macOS (rbenv on Linux). No etch-cli action for chruby setup. `ruby.install` handles ruby-install invocation but not chruby prefix/shim config. Needs `ruby.chruby` or a `version_manager: chruby` field on ruby.install. macOS-only.                                             |
| tfenv action                | setup_env.sh installs tfenv via git clone + symlinks to manage Terraform versions. No etch-cli action. Could be `terraform.tfenv` with `version:` field. Idempotency: skip if `~/.tfenv` exists and requested version is installed.                                                                                         |
| etch update selective flags | `etch update` runs all update categories. setup_env.sh supports `--brew-only`, `--pip-only`, `--gems-only`, `--mas-only`, `--pkgs-only`, `--claude-only`. Add equivalent `--only <category>` or `--skip <category>` flags to `etch update`.                                                                                 |
| etch doctor subcommand      | setup_env.sh has a `doctor` mode that validates: symlink integrity (dotfile links point to real targets), tool existence in PATH, credential dir permissions (mode 700 for ~/.ssh, ~/.tf_creds, ~/.tsh), version drift (installed vs pinned). `etch status` covers manifest drift; `etch doctor` would cover system health. |
| binary.get version drift    | `binary.get` downloads a pinned GitHub release but has no way to detect when a newer version is available. setup_env.sh fetches latest tag from GitHub API and compares against constants.sh pins. `etch status` could report drift for binary.get atoms where `version:` is set.                                           |

## Adding a new entry

When a new spec or plan is created, add a row to the All Plans table. Set status to **In Progress** when implementation starts, **Done** when the PR merges. Also add a `> **Status: DONE**` banner at the top of the plan file once complete. Move backlog items to the All Plans table when their spec is written (remove the backlog row).
