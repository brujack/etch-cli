# gix 0.80 → 0.87 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `gix` from 0.80.0 to 0.87.0, clearing 23 high-severity Dependabot alerts, and add the one test that makes the bump verifiable.

**Architecture:** Three sequential tasks. Task 1 adds a local-clone test **against the current 0.80** so the instrument is calibrated before it is used. Task 2 performs the bump and the mechanical API fix. Task 3 closes documentation. The ordering is load-bearing: a test added after the bump that fails cannot distinguish "the bump broke cloning" from "the test is wrong."

**Tech Stack:** Rust, `gix`, `cargo nextest`, `tempfile`, `serial_test`.

## Global Constraints

- Target is **0.87.0** (current release), not 0.83.0 (minimum patched). Copied verbatim from the spec: the API-break cost is identical at either target.
- Scope is **gix only**. `quinn-proto`, `tar`, `serde_with` and the `deny.toml`-ignored `hickory-proto` are out of scope and separately backlogged.
- The new test **must not require network**. gix parses `InputScheme::Local`, so a filesystem path exercises the real chain.
- The new test **must be `#[serial]`**. Two existing tests in the same module mutate process-wide `PATH` to install a mock `git`; Rust tests share a process, so a non-serial fixture calling `git init` can pick up that mock and build no real repository.
- The new test **must target a non-existent destination directory**. `execute()` returns early via `git -C <dir> pull` when `update_existing && directory.exists()`; a test built the obvious way would take that branch, pass, and verify nothing about gix.
- Coverage will rise above the 81% floor. **Report the figure, do not ratchet the gate** — ADR-0004 raises the floor on sustained measurement, not on one PR.

## Session-Level Verification (per behavior.md)

**Command that proves the whole change works:** `make test` on the post-bump tree, with the new test present and passing.

**Expected observable change:** `cargo tree -p gix` reports 0.87.0; `make test` reports 65 Rust tests passing (64 + the new one); `cargo deny check advisories` reports `advisories ok`.

**Edge cases exercised:** the gix clone branch specifically (not the shell-out branch), asserted on cloned file _content_ rather than an `Ok` return.

**Post-merge only, cannot gate the PR:** `gh api repos/brujack/etch-cli/dependabot/alerts?state=open --jq 'length'` drops from 28 to ~5. The alert set is recomputed against the default branch after merge. Recorded as a post-merge step, not presented as a gate.

### Task 1: Add a local-clone test on the current gix 0.80

```yaml-task

role: executor

tdd: required
acceptance:
  - cmd: 'grep -q "fn clone_local_repo_via_gix" lib/src/atoms/git/clone.rs'
    exit_code: 0
  - cmd: 'cargo nextest run -p etch-lib -E "test(clone_local_repo_via_gix)"'
    exit_code: 0
  - cmd: make test
    exit_code: 0
max_retries: 3
files_touched:
  - lib/src/atoms/git/clone.rs
depends_on: []
```

**Files:** `lib/src/atoms/git/clone.rs` — append one test to the existing `#[cfg(test)] mod tests`.

**Steps:**

- [ ] Write `#[test] #[serial] fn clone_local_repo_via_gix()` in the existing `mod tests`.
- [ ] Fixture: `let src = tempfile::tempdir().unwrap();` then shell out to build a real repo. Strip the git environment on **every** invocation — `.env_remove("GIT_DIR").env_remove("GIT_WORK_TREE").env_remove("GIT_INDEX_FILE")` — matching what `execute()` already does at `lib/src/atoms/git/clone.rs:57-59`. Without it a leaked `GIT_DIR` makes `git init` operate on the wrong repository.
    - `git init`, `git config user.email`, `git config user.name` (repo-local, so no dependency on global identity)
    - write `hello.txt` containing `gix-roundtrip`
    - `git add hello.txt`, `git commit -m fixture`
- [ ] Destination: `let dest = tempfile::tempdir().unwrap().path().join("clone");` — a path that does **not** exist. Do not create it.
- [ ] Build the atom: `Clone { repository: gix::url::parse(src.path().to_string_lossy().as_bytes().into()).unwrap(), directory: dest.clone(), update_existing: false }`. Note `update_existing: false` and a non-existent `dest` both independently force the gix branch.
- [ ] Assert three things: `execute()` is `Ok`; `dest.join(".git").exists()`; and `std::fs::read_to_string(dest.join("hello.txt")).unwrap().trim() == "gix-roundtrip"`.
- [ ] Run the acceptance gates. Confirm `make test` reports 65 tests.
- [ ] **Mutation check — required, report the output.** Comment out the `atom.execute()` call and re-run `cargo nextest run -p etch-lib -E "test(clone_local_repo_via_gix)"`. It MUST fail on the content assertion. Restore. A test that passes with the clone removed is asserting on the fixture, not the clone.
- [ ] Commit via `caveman:caveman-commit`.

**Interfaces:**

- Consumes: `Clone { repository: gix::Url, directory: PathBuf, update_existing: bool }` and `Atom::execute(&mut self) -> anyhow::Result<()>`, both already in this file.
- Produces: test name `clone_local_repo_via_gix`, referenced by Task 2's gate.

**Why this task exists and runs first:** the gix execution path has no coverage today. Six of the module's eight tests exercise `plan()`; the two that call `execute()` set `update_existing: true` against an existing directory and take the shell-out branch against a mocked `git`. Calibrating the instrument on 0.80 is what lets Task 2's result be interpreted.


`tdd: not-applicable` — the test that verifies this bump is Task 1's deliverable, written first and deliberately. This task adds no new behaviour of its own.

**Steps:**

- [ ] Set `version = "0.87.0"` in the `gix` dependency of `lib/Cargo.toml` and `app/Cargo.toml`. Leave the feature lists unchanged.
- [ ] `cargo check --workspace --all-targets` — expect ~14 `E0283: cannot satisfy _: AsBStr` errors. This is the predicted state, not a failure.
- [ ] Fix every one by the same substitution. `gix::url::parse` is now `pub fn parse(input: impl AsBStr)`, so the bare `.into()` no longer resolves:

    ```rust
    gix::url::parse(x.as_str().into())      // before — E0283
    gix::url::parse(x.as_str().as_bytes())  // after — &[u8] satisfies AsBStr
    ```

    Production sites: `lib/src/actions/git/clone.rs`, `lib/src/actions/git/pull.rs`, `lib/src/actions/zsh/oh_my_zsh.rs`, `lib/src/manifests/providers/git.rs`. Roughly ten more in test bodies, including Task 1's own new test.

- [ ] Do **not** invent other fixes. Every error should be this one pattern; anything else is a genuine behaviour change and is a `blocker` — report it rather than working around it.
- [ ] Run the acceptance gates. `make test` must report 65 tests.
- [ ] Report the tarpaulin figure if convenient, but do **not** change `--fail-under 81` in `.github/workflows/ci.yml`.
- [ ] Commit via `caveman:caveman-commit`.

**Interfaces:**

- Consumes: `clone_local_repo_via_gix` from Task 1 — the gate that distinguishes "compiles" from "still clones."
- Produces: `gix` at 0.87.0 in `Cargo.lock`.

## Notes for the implementer

**A name-filtered `cargo nextest` run exits 4, not 1, when the test does not exist.** Measured. That is a usage error rather than a test failure, which is why each gate pairs the filtered run with a `grep` for the function name — the grep gives a clean exit 1 on the pre-change tree. Do not read a bare `rc=4` as "the test failed."

**The wrong implementation these gates are blind to** — stated explicitly per the plan skill's third question — is a Task 1 test that asserts on the _source fixture_ rather than the _cloned destination_. `make test` and the filtered run both pass it. The mutation step in Task 1 is the only thing that catches it, which is why it is a required step with reported output rather than advice.
